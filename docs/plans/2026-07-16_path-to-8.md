# Path to 8/10 — Nocturnal vs competitive notch demo

**Date:** 2026-07-16  
**Baseline:** ~3.5–4 / 10 (honest feature parity with Bren-style demo)  
**Target:** **≥ 8 / 10** on the same scorecard  
**Constraint:** Local-first, fail-open, monochrome owl brand, **no invented telemetry**  
**Related:** `docs/plans/2026-07-16_notch-feature-expansion.md` (P0 already largely shipped)

---

## 1. What “8” means

An **8** is not a pixel clone. It means:

1. Someone watching both demos feels **the same product category and power**.
2. Rows and detail answer: *what is it doing, on what, for how long, and do I need to act?*
3. Approvals feel like a **control surface**, not a modal afterthought.
4. Timeline + last signal feel **continuous and trustworthy**.
5. 1–2 “ops” surfaces exist (servers and/or usage) **only when real local data exists**.

An **8 is not**:

- Fake tokens / diffs / 5H–7D %
- Glass/neon island clone
- Full agent console / transcript mirror
- Breaking fail-open or writing real `~/.codex` from tests

### Scoreboard (baseline → target)

| Surface | Now | Target 8 | Delta strategy |
|---------|----:|---------:|----------------|
| Notch compact live | 6 | **8.5** | Motion, verb chip, multi-session dots, attention morph |
| Session list richness | 4 | **8** | Tool chips, commands, paths, elapsed, attention cards |
| Approval UX | 6 | **8.5** | Inline primary surface, plan parse, code block, success beat |
| Question UX | 3 | **7.5** | Multi-choice polish, sequential queue, multi-select when payload says so |
| Session detail / timeline | 3.5 | **8** | Bounded JSONL tail + richer activity model |
| Usage / servers / config | 1.5 | **7** | Local file usage **if present** + listener scan **opt-in** |
| **Overall** | **~4** | **≥ 8** | Weighted toward list + detail + approval |

## 2. The real problem: data ladder

UI polish alone maxes out ~**5.5**. Reaching **8** requires a **data ladder**:

```text
L0  Hooks we already decode (lifecycle, Pre/PostToolUse, permission, question)
L1  Richer decode of the same payloads (tool_input, commands, paths, nested fields)
L2  Bounded local file readers (Codex JSONL tail, Claude history if shape known)
L3  Opt-in local system probes (listening ports / child processes of known agents)
L4  Never: invent numbers, scrape cloud usage APIs, clone proprietary chrome
```

| Competitive UI | Lowest honest level |
|----------------|---------------------|
| Live verb / command | L0–L1 |
| File path / tool name chips | L1 |
| Diff +/− | L2 (git or tool result parse) **or omit** |
| Token up/down | L2 if present in JSONL/events **or omit** |
| Last reply text | L2 bounded tail of assistant messages |
| Timeline depth | L0–L2 |
| 5H / 7D usage | L2 only if vendor files exist on disk |
| Local servers | L3 opt-in |

**Rule:** Every number on screen must have a **provenance** (`hook`, `jsonl`, `git`, `portscan`). If provenance missing → hide field, never `0` as decoration.

## 3. Target product surfaces (end state)

### 3.1 Compact notch (8.5)

- Verb chip (semantic color) + truncated command/path.
- Attention morph: wider drip / amber pulse when approval pending.
- Multi-session: up to 3 quiet dots or source glyphs when N>1.
- Click expands; hover (optional) shows one-line project name.

### 3.2 Session rows (8)

Each row is a **dense card**:

| Slot | Content | Source |
|------|---------|--------|
| Title | Project / cwd basename | L0–L1 |
| Live | Verb · command or path | L1 |
| Meta | `12m · 6 tools · 3 files` | L0–L1 stats |
| Chips | monochrome `bash` `read` `git` `github` | L1 tool map |
| Jump | Codex / Cursor / Terminal badge | L0 jumpBack |
| Attention | Full-width tint when pending | L0 state |

**Still omit** tokens/diffs until L2 proves real fields.

### 3.3 Expanded shell (8)

- Header: count, attention, live strip, Folders, Settings, optional **Refresh listeners**.
- **Master–detail:** list left/top; **selected session inspector** sticky bottom or side.
- When any session needs attention: **Approval rail** pinned above list (not buried in sheet only).

### 3.4 Approvals (8.5)

- Banner + tool + risk.
- Detail: monospaced; if text looks like numbered plan → render as list.
- If detail looks like code/patch → fenced code block (no heavy highlighter required).
- Actions: Deny · Deny+note · Always allow (session) · Allow; shortcuts stable.
- Success: 0.6s monochrome check strip (“Recorded”) then return to list.
- Copy always **recorded**, never “agent accepted”.

### 3.5 Questions (7.5)

- Radios / Other / freeform (done).
- **Queue:** if multiple `waitingForInput` sessions or sequential prompts, show `1 of N` across **sessions or prompts we actually have** — never invent sections.
- Multi-select only when payload has explicit multi flag / array answers.

### 3.6 Detail + timeline (8)

- **Last signal:** prefer L2 last assistant/user snippet; else last finished activity / summary.
- **Timeline:** merge hook activities + optional L2 tool rows; cap 50 display / 12–24 persisted hot.
- Per row: symbol, label, detail, duration, optional exit status if known.
- Collapsible “Show more”.

### 3.7 Ops (7 combined)

**A. Listeners (opt-in setting, default off or on only when detected)**  
Scan for LISTEN sockets owned by common agent/dev processes *or* cwd-associated ports from session env if present. Show host:port, guessed stack label (heuristic), open URL, reveal. **No kill-by-default** in v1 (stop = optional later).

**B. Usage (display only if files exist)**  
Probe known local paths (document each): e.g. Claude/Codex rate-limit or usage JSON if discoverable. Show raw remaining or last-updated — **not** fake “5H: 63%” unless that exact metric exists.

**C. Config grid**  
Extend folders: Skills / Plugins / Config / Logs / Root **only when those directories exist** under `~/.codex` / `~/.claude`.

## 4. Core model changes (to unlock 8)

### 4.1 Richer activity (L1)

Extend `SessionActivity` / mapping:

```text
kind, label, detail, eventType, startedAt, endedAt   // existing
+ toolName: String?
+ primaryPath: String?
+ command: String?
+ integration: enum?  // shell, filesystem, git, github, web, mcp, unknown
+ outcome: success | failure | unknown   // from PostToolUse if present
```

Decoders extract from Pre/PostToolUse / PermissionRequest `tool_input` aggressively but fail-open.

### 4.2 Session metrics (L1–L2, optional fields only)

```text
SessionStats (extend, all optional/zero-safe):
  toolUseCount, filesTouchedCount, …   // existing
  + lastCommand: String?
  + integrationCounts: [String: Int]?  // bounded
  // ONLY if L2 provides real values:
  + tokensIn: Int?
  + tokensOut: Int?
  + diffAdded: Int?
  + diffRemoved: Int?
```

UI shows token/diff **only when non-nil**.

### 4.3 Session detail blob (L2)

```text
SessionDetailSnapshot:
  lastUserSnippet: String?     // bounded chars
  lastAssistantSnippet: String?
  recentToolRows: [SessionActivity]  // may exceed hot recentActivities
  source: hook | jsonl
  capturedAt: Date
```

Store holds **latest snapshot per session**; regenerated by a **bounded reader actor**, never UI.

### 4.4 Codex / Claude local readers (L2)

| Reader | Input | Output | Safety |
|--------|-------|--------|--------|
| `CodexRolloutTailReader` | known `transcript_path` or sessions tree | last N tool/assistant events | max bytes, max lines, no full file load |
| `ClaudeHistoryTailReader` | only if path shape confirmed | same | same |
| Extend `CodexTranscriptScanner` | keep session_meta for recovery | do **not** replace live hooks | fail-open |

**Policy:** Live hooks remain authoritative for `state` / pending approval. JSONL **enriches** detail/timeline only.

### 4.5 Listeners (L3)

```text
LocalListener:
  host, port, pid?, processName?, cwdHint?, label?
LocalListenerProbe actor:
  refresh() -> [LocalListener]
```

Setting: `scanLocalListeners: Bool` (schema bump). Default **false** until QA’d, or true only in DEBUG — product call.

### 4.6 Response / always-allow

Already have local sticky. For 8:

- Persist sticky across relaunch (already on Session if persisted).
- Optional: “Always allow this tool **until session ends**” clear on terminal state (document).

## 6. Phased roadmap (to hit 8)

### Phase A — “Looks powerful on real hooks” (~2–3 days)

**Goal:** Overall **~6.0** without L2 files.

1. **W2** Rich `tool_input` → command/path/integration on activities + approval detail.
2. **W1** Redesign `SessionRowView`: 3-line density, chips, command ellipsis, attention card.
3. **W3** Inline approval rail in expanded overlay when any `pendingApproval`; plan list heuristic; success strip.
4. **W10** Pill: stronger verb hierarchy; multi-session indicators.
5. **W6** Question: radio polish already partial; add session-level queue indicator if multiple waiting.
6. **W11** Fixtures: PreToolUse with nested tool_input; approval with multi-line plan; multi-session socket script.

**Exit criteria**

- [ ] Demo with 4 fixture sessions looks “busy and real,” not sparse.
- [ ] Approval rail visible without opening a separate mental model.
- [ ] `swift test` green; no fake numbers.

### Phase B — “Detail feels alive” (~2–3 days)

**Goal:** Overall **~7.0–7.5** with L2.

1. **W5** `CodexRolloutTailReader` (and Claude if documented): last assistant snippet + tool rows.
2. **W4** Inspector panel: Last signal + Timeline v2 (merge hook + jsonl, dedupe by time/label).
3. Surface **tokens/diff only if reader finds them**.
4. Expand `recentActivities` policy or separate `detailTimeline` cap (e.g. 40) for UI.
5. Simulation doc: “rich demo” recipe using local fixture JSONL.

**Exit criteria**

- [ ] Selecting a Codex session with a real/fixture rollout shows non-empty Last signal **from file or hooks**.
- [ ] Timeline ≥ 8 meaningful rows in demo fixture.
- [ ] Reader hard limits unit-tested (byte/line caps, no hang on huge files).

### Phase C — “Ops credibility” (~1–2 days)

**Goal:** Overall **≥ 8.0**.

1. **W7** Config grid: Skills/Plugins/Config/Logs/Root when dirs exist.
2. **W8** Optional listener probe + UI list (open in browser).
3. **W9** Usage: only if local usage files found — otherwise keep header clean (no empty meters).
4. Notch compact polish pass (spacing, attention morph).
5. End-to-end packaged smoke: `Scripts/package_app.sh` + fixture inject.

## 8. Architecture sketch

```text
Hooks ──► SessionStore.apply ──► Session + currentActivity + stats
                │
                ├── AppModel snapshot ──► Pill / Rows / Approval rail
                │
JSONL tail reader (actor, bounded) ──► SessionDetailSnapshot ──► Inspector
                │
Listener probe (opt-in actor) ──► [LocalListener] ──► Servers tab
                │
Usage probe (opt-in, evidence paths) ──► UsageSnapshot? ──► Header meters or hide
```

**Concurrency:** readers are actors; UI only observes snapshots; never parse files on MainActor beyond trivial existence checks.

## 11. Risks

| Risk | Mitigation |
|------|------------|
| JSONL format drift | Version probes; fail-open empty detail |
| Performance on huge rollouts | Hard byte/line caps; sample from end of file |
| Privacy (reading transcripts) | Local only; no upload; settings toggle “Read local agent logs for detail” default **on** for companion value but documented |
| Listener false positives | Heuristics + show process name; no auto-kill |
| Scope creep back to clone | Scorecard + non-goals review each phase |
| Lying with partial data | Provenance rule; hide nils |
