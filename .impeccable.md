# Nocturnal Design Context

## Product

**Nocturnal** — a free, local-first macOS companion for AI coding agents. It sits quietly in the menu bar (and an optional floating pill), surfaces session state and approvals, and gets out of the way.

## Brand personality

- **Monochrome owl** — Vercel-inspired black, white, and neutral grays; precise and quiet
- **Native & precise** — feels like a system utility, not a startup landing page
- **Trustworthy** — clear states, no dark patterns, no urgency theater
- **Owl mark** — transparent monochrome glyph; app icon is full-bleed source art

## Anti-references (do not ship)

- Neon / cyberpunk / matrix greens
- Cyan–purple “AI gradients”
- Glassmorphism blobs, heavy blur stacks, generic card grids
- Copied proprietary “island” chrome from third-party products (our notch extension is original: black top-flush drip, monochrome, no glass/neon)
- Loud badges, confetti, gamification
- Warm brown/umber tints or decorative color accents
- Rectangular chrome or rectangular shadows around the compact pill

## Color

| Token | Role | Guidance |
|-------|------|----------|
| `bg.base` | App / panel background | Near-black neutral, e.g. `#0A0A0A` |
| `bg.elevated` | Menus, elevated rows | Slightly lighter gray (`#141414`) |
| `fg.primary` | Titles | Soft white (`#EDEDED`) |
| `fg.secondary` | Summaries | Mid neutral gray |
| `accent.attention` | Approvals / questions only | Restrained amber — semantic, not decorative |
| `accent.danger` | Failures / deny only | Desaturated red, used sparingly |
| `accent.success` | Completed only | Muted green, not neon |
| `border.subtle` | Separators | Low-contrast neutral hairlines |

**Rule:** black, white, and neutral grays only for chrome. Semantic colors appear only where approval, warning, failure, or success truly require meaning. Prefer system semantic styles first.

No gradients. No glassmorphism. No colored decorative accents.

## Typography

- System SF Pro / SF Pro Rounded sparingly for wordmark only if needed
- Hierarchy: **headline** (app name) → **subheadline semibold** (session title) → **caption** (summary/meta)
- Monospaced caption2 for raw state chips only

## Layout

- Menu bar window ~320pt wide; comfortable list density
- Floating pill: notch extension (~272×38), **flush to screen top**, top-flat / bottom-rounded black drip
- Compact pill: no rectangular window shadow or hosting fill; black fill merges with camera housing
- Expanded panel: hangs from screen top (~520×620, clamped), one column, stable `ForEach` identity by `Session.id`
- Live activity line on pill + rows from hook-derived `Session.currentActivity`
- Generous padding (12–16); avoid cramped toolbars

## Motion

- Default: short, damped (≈0.2s) opacity/position — **no** bounce for primary UI
- Respect **Reduce Motion** (`AppSettings.reduceMotion` + system setting): cross-fade only or instant
- Attention pulse for approvals: optional, single subtle breath — never infinite aggressive blink
- Sound: **off by default** (`soundEnabled`)

## Accessibility

- Every interactive control is a `Button` (or `SettingsLink`) with a clear label
- Session rows combine accessibility elements; include title, state, source
- Status line exposed as live-ish text (VoiceOver label “Status: …”)
- Keyboard: full menu navigation; key equivalents for Approve/Deny
- Dynamic Type: prefer text styles over fixed font sizes
- Contrast: attention accent must meet legible contrast on `bg.elevated`

## Imagery / iconography

- **Owl mark** (`nocturnal-owl-mark.png`) — transparent glyph for menu bar (template), pill, headers, empty state, about
- **App icon** (`nocturnal-app-icon.png`) — full-bleed source → packaged `.icns`
- No SF Symbol moon substitutes when the mark is available
- No stock “robot / neural net” illustrations

## Tone of copy

- Short, calm, specific: “Approve shell command?” not “Action Required!!!”
- Errors explain next step without blame
- Empty state: Codex and Claude sessions appear after hooks are connected; offer Settings and setup command actions

## Implementation notes for UI agent

- SwiftUI first; AppKit only for non-activating overlay panel
- `@Observable` `AppModel`; no business logic in views
- Brand tokens live in `DesignTokens.swift`; brand images via a tiny reusable helper
- No product demo mode — empty state is the first-run path
