# Nocturnal Design Context

## Product

**Nocturnal** — a free, local-first macOS companion for AI coding agents. It sits quietly in the menu bar (and an optional floating pill), surfaces session state and approvals, and gets out of the way.

## Brand personality

- **Quiet nocturnal** — late-night studio, not a rave
- **Native & precise** — feels like a system utility, not a startup landing page
- **Warm dark** — charcoal with a slight brown/umber tint; never pure #000 cold black
- **Trustworthy** — clear states, no dark patterns, no urgency theater

## Anti-references (do not ship)

- Neon / cyberpunk / matrix greens
- Cyan–purple “AI gradients”
- Glassmorphism blobs, heavy blur stacks, generic card grids
- Copied “island / notch toy” aesthetics from other products
- Loud badges, confetti, gamification

## Color

| Token | Role | Guidance |
|-------|------|----------|
| `bg.base` | App / panel background | Warm near-black, e.g. hsl(30 8% 8%) |
| `bg.elevated` | Menus, expanded panel | Slightly lighter warm charcoal |
| `fg.primary` | Titles | Soft warm off-white |
| `fg.secondary` | Summaries | Muted warm gray |
| `accent.attention` | Approvals / questions | Soft amber / copper — not alarm red by default |
| `accent.danger` | Failures / deny | Desaturated red, used sparingly |
| `accent.success` | Completed | Muted sage, not neon green |
| `border.subtle` | Separators | Low-contrast warm hairlines |

Prefer semantic SwiftUI styles (`.primary`, `.secondary`, `.quaternary`) first; introduce custom `Color` assets only when system colors cannot express warmth.

## Typography

- System SF Pro / SF Pro Rounded sparingly for wordmark only if needed
- Hierarchy: **headline** (app name) → **subheadline semibold** (session title) → **caption** (summary/meta)
- Monospaced caption2 for raw state chips only

## Layout

- Menu bar window ~320pt wide; comfortable list density
- Floating pill: compact single line (~220×36), top-center or notch-aware
- Expanded panel: one column, stable `ForEach` identity by `Session.id`
- Generous padding (12–16); avoid cramped toolbars

## Motion

- Default: short, damped (≈0.2s) opacity/position — **no** bounce for primary UI
- Respect **Reduce Motion** (`AppSettings.reduceMotion` + system setting): cross-fade only or instant
- Attention pulse for approvals: optional, single subtle breath — never infinite aggressive blink
- Sound: **off by default** (`soundEnabled`)

## Accessibility

- Every interactive control is a `Button` (or `SettingsLink`) with a clear label
- Session rows combine accessibility elements; include title, state, source
- Status line exposed as live-ish text (VoiceOver label “Status: …”)
- Keyboard: full menu navigation; future: key equivalents for Approve/Deny
- Dynamic Type: prefer text styles over fixed font sizes
- Contrast: attention accent must meet legible contrast on `bg.elevated`

## Imagery / iconography

- SF Symbol `moon.stars.fill` as interim mark
- No stock “robot / neural net” illustrations
- Future custom mark: simple moon / quiet glyph, monochrome

## Tone of copy

- Short, calm, specific: “Approve shell command?” not “Action Required!!!”
- Errors explain next step without blame
- Empty state: what will happen when hooks fire, not marketing

## Implementation notes for UI agent

- SwiftUI first; AppKit only for non-activating overlay panel
- `@Observable` `AppModel`; no business logic in views
- Brand tokens may live in a small `DesignTokens.swift` when UI lands
- Demo mode must look first-class, not “debug placeholder”
